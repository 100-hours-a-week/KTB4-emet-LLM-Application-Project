# 도메인 구매부터 배포까지 트러블슈팅 정리

## 1. 도메인 구매
- **Cloudflare Registrar**에서 도메인 구매
- 비용: 연 $10.46 (마크업 없는 원가 + ICANN 수수료 $0.18 포함)
- 등록 기간: 1년 단위, 갱신가도 등록가와 동일

## 2. EC2 연결 준비
- 기존 퍼블릭 IP는 인스턴스 재시작 시 변경될 수 있음
- → **Elastic IP 할당 및 인스턴스 연결(Associate)** 로 고정 IP 확보
- 주의: Elastic IP는 인스턴스에 연결된 상태에서는 무료, 연결 해제 상태로 방치하면 과금됨

## 3. Cloudflare DNS 설정
- Cloudflare 대시보드 → DNS → Records → A 레코드 추가
  - Type: `A`
  - Name: `@` (루트 도메인)
  - IPv4 address: Elastic IP
  - Proxy status: DNS only (회색 구름, SSL 세팅 전까지 유지)

### 시행착오 #1 — www 서브도메인 미등록
- `www.도메인`으로 접속/조회 시도 시 실패
- **원인**: 루트(`@`)에만 A 레코드를 등록해서 `www` 서브도메인은 별도 매칭이 안 됨
- **해결**: 필요 시 `www` 이름으로 별도 A 레코드 추가, 또는 CNAME으로 루트를 가리키게 설정

## 4. GitHub Actions 배포 실패 #1 — IP 불일치
```
dial tcp 3.90.153.19:22: i/o timeout
```
- **원인**: Elastic IP를 새로 할당하면서 IP가 변경됐는데, GitHub Secrets의 `HOST` 값이 이전 IP로 남아있었음
- **해결**: Secret 값을 새 IP 대신 **도메인 이름**으로 교체
  - 장점: 이후 IP가 바뀌어도 DNS 레코드만 수정하면 되므로 Secret을 다시 건드릴 필요 없음

## 5. Secret 입력 실수
- `https://도메인` 형태로 입력했다가 SSH 접속 실패
- **원인**: `ssh-action`은 순수 호스트명만 받음, 프로토콜(`https://`, `http://`)이나 슬래시(`/`), 포트 번호를 붙이면 안 됨
- **해결**: `example.com` 형태로만 입력

## 6. DNS 확인 단계 혼동
- `www.도메인`으로 nslookup 시 "서버를 찾을 수 없음" 발생 → 3번(www A 레코드 미등록)과 동일한 원인
- 루트 도메인으로 재확인하니 정상적으로 Elastic IP(`34.235.65.52`) 응답 확인

## 7. GitHub Actions 배포 실패 #2 — 보안그룹
- `nc -zv 도메인 22` 테스트 시 연결 실패 (timeout)
- **원인**: EC2 보안그룹 인바운드 규칙에 **22번(SSH) 포트**가 열려있지 않았음
- **해결**: 보안그룹 → 인바운드 규칙 추가
  - Type: SSH, Port: 22, Source: 0.0.0.0/0

## 8. 배포 성공
- SSH 연결 성공 → GitHub Actions의 `ssh-action`이 EC2 내부에서 자동으로 아래 명령 실행
  1. `docker pull` (최신 이미지)
  2. `docker stop` / `docker rm` (기존 컨테이너 정리)
  3. `docker run -d` (신규 컨테이너 기동)
- 사람이 EC2에 직접 접속해 docker 명령어를 칠 필요 없이 전 과정 자동화 확인됨

## 핵심 교훈
Elastic IP 재할당 등 **인프라 변경 후에는 아래 3곳을 함께 점검**해야 배포 파이프라인이 끊기지 않음:

| 점검 대상 | 확인 내용 |
|---|---|
| DNS (Cloudflare) | A 레코드가 최신 Elastic IP를 가리키는지 |
| GitHub Secrets | `HOST` 값이 최신 IP/도메인과 일치하는지 |
| EC2 보안그룹 | 22(SSH), 80(HTTP), 443(HTTPS) 포트가 열려있는지 |

### 로컬(맥북) vs 서버(EC2) 확인 구분
- **로컬에서 확인**: `nslookup`, `curl`, `nc -zv` (DNS 전파, 외부 접속 가능 여부)
- **EC2 서버 안에서 확인**: `ps aux | grep uvicorn`, `sudo systemctl status nginx` (서버 프로세스 자체 상태)
