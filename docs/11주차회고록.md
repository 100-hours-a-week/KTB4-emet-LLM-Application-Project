## 금주 최신화 정보
### 1. 설계
#### 1-1. 로드맵 작성
- 전체적인 로드맵과 마일즈 스톤 수정(07.28(수))
- https://github.com/100-hours-a-week/KTB4-emet-LLM-Application-Project/blob/main/Roadmap.md

#### 1-2.현재 개발된 플로우 차트 (ver_0.2)
- 지난주의 플로우차트 초안을 재검토하고, 보완함
- Claude를 이욜해서 전체적인 플로우 차트 생성

### 2. 개발 진행상황
#### 2.1. 멀티턴 도입
  - 멀티턴을 위해서 thread_id와 체크포인터 추가
#### 2.2. 추출한 재료 분석
  - 식용 가능 여부, 재료들의 조합, 재료로 요리레시피가 생성가능한지 판단
  - 레시피 생성 가능/ 추가 재료로 레시피 생성가능 / 레시피 생성 불가능 정보 리턴
  - 추가 재료로 레시피 생성 가능하다면 최소한으로 추가하는 재료 리스트 같이 생성
#### 2.3. 예비 선택 레시피 생성
  - 추출한 재료와 추가재료로 예비 선택지(프리뷰 레시피) 생성
  - 프리뷰 레시피: 요리이름과 추가재료 정보를 가짐
#### 2.4. RAG 예비 레시피 변환
  - 추출한 재료에서 RAG 레시피의 재료들의 차집합을 구해서 예비 선택 레시피와 같은 형태로 추가 재료와 요리이름 추출
#### 2.5.선택지 통합 응답
  - 예비 선택 레시피 생성, RAG 예비 레시피 변환에서 얻은 예비선택지(프리뷰레시피)를 추가재료가 적은순으로 나열하고 사용자에게 응답

#### 2.6.질의 분석
- 새로운 타입 "레시피 선택" 추가
  - 사용자와 재료추출과정을 거쳐서 프리뷰레시피 정보를 가진상태에서, 레시피 선택에 대한 내용이라면 해당 방향으로 진행
    
#### 2.7. 레시피 선택
- 1) 번호 일치 -> 요리이름 일치 -> LLM 순으로 프리뷰 레시피를 선택하도록 구현
  - 문제점: 해당 방식은 만약에 "2번 말고 3번으로 할께", "게살볶음밥랑 계란볶음면 먹고싶어"와 같은 애매모호한 중의적질의에서 문제 발생
- 2) 위의 중의적을 프롬프트에 추가해서 LLM이 자체적으로 판단하도록 구현

#### 2.8. 최종 레시피 생성
- 레시피 선택에서 이전 예비선택지 생성의 요리를 골랐다면 진행, 요리이름과 재료(추출+추가)를 기반으로 정형화된 레시피 생성하고 사용자에게 응답
- 
#### 2.9. RAG 레시피 
- 레시피 선택에서 RAG 레시피를 골랐다면 진행, RAG 레시피 정보를 사용자에게 응답

## 차주 목표
### 1. 흐름 개선
#### 1.1. 레시피 추천 -> 레시피 추천 버그 발생
- 이전 프리뷰 레시피 가진채로 그대로 같이 출력(중복 출력,재료 표시잘못된 출력)
- 레시피 추천 -> 레시피 추천은 이전 레시피정보를 삭제하도록 수정 예정
### 2. 성능 판단
#### 2.1. 레시피 평가
- 먹을 수 있는 레시피를 생성하는지 검증하는 방법 랭스미스로 구현
### 3. 개발 목표
#### 3.1. 레시피 검토기능 개발
  - 최종 레시피 생성이 생성한 레시피가 먹을 수 있는 레시피인지 판단

#### 3.2. 플로우차트 루프백 검토
  - 루프백이 필요한 부분 기능 추가
#### 3.3. 레시피 응답 전체 플로우 생성 
  - 레시피 생성이후 반응에 따른 흐름
### 4. 그래프 -> 에이전트화
#### 4.1 멀티에이전트
  - 현재 구현한 노드들을 툴로 변환해서 멀티에이전트 형태 구상중
  - 구성도 초안
