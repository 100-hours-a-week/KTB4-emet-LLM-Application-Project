### 개발 진행상황
#### 멀티턴 도입
  - 멀티턴을 위해서 thread_id와 체크포인터 추가
#### 추출한 재료 분석
  - 식용 가능 여부, 재료들의 조합, 재료로 요리레시피가 생성가능한지 판단
  - 레시피 생성 가능/ 추가 재료로 레시피 생성가능 / 레시피 생성 불가능 정보 리턴
  - 추가 재료로 레시피 생성 가능하다면 최소한으로 추가하는 재료 리스트 같이 생성
#### 예비 선택 레시피 생성
  - 추출한 재료와 추가재료로 예비 선택지(프리뷰 레시피) 생성
  - 프리뷰 레시피: 요리이름과 추가재료 정보를 가짐
#### RAG 예비 레시피 변환
  - 추출한 재료에서 RAG 레시피의 재료들의 차집합을 구해서 예비 선택 레시피와 같은 형태로 추가 재료와 요리이름 추출
#### 선택지 통합 응답
  - 예비 선택 레시피 생성, RAG 예비 레시피 변환에서 얻은 예비선택지(프리뷰레시피)를 추가재료가 적은순으로 나열하고 사용자에게 응답

#### 질의 분석
- 새로운 타입 "레시피 선택" 추가
  - 사용자와 재료추출과정을 거쳐서 프리뷰레시피 정보를 가진상태에서, 레시피 선택에 대한 내용이라면 해당 방향으로 진행
    
#### 레시피 선택
- 1. 번호 일치 -> 요리이름 일치 -> LLM 순으로 프리뷰 레시피를 선택하도록 구현
  - 문제점: 해당 방식은 만약에 "2번 말고 3번으로 할께", "게살볶음밥랑 계란볶음면 먹고싶어"와 같은 애매모호한 중의적질의에서 문제 발생
- 2. 위의 중의적을 프롬프트에 추가해서 LLM이 자체적으로 판단하도록 구현

#### 최종 레시피 생성
- 레시피 선택에서 이전 예비선택지 생성의 요리를 골랐다면 진행, 요리이름과 재료(추출+추가)를 기반으로 정형화된 레시피 생성하고 사용자에게 응답
#### RAG
- 레시피 선택에서 RAG 레시피를 골랐다면 진행, RAG 레시피 정보를 사용자에게 응답
