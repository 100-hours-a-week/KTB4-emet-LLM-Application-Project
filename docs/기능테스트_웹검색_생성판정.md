# 기능 테스트 — 웹 검색 기반 요리 실존 판정 (1차, 2026-08-07)

`nodes/name_search.py`의 `generate_recipe_by_name`(RAG에 매칭이 없을 때 웹 검색으로 실존 여부를 먼저 확인한 뒤 생성)에 대한 1차 테스트 기록. 두 단계로 진행:

1. **웹 검색 함수 자체(`rag/web_search.py`)** 원본 결과 확인 — LLM 개입 없음, Tavily 순수 결과
2. **판정 프롬프트 개선 전/후** — 1차 원본 검색에서 발견한 "그럴듯하지만 무관한 결과" 문제를 `generate_recipe_by_name_prompt`에 반영한 뒤, 같은 10개 요리명으로 `generate_recipe_by_name` 전체 로직(검색+LLM 판정) 재테스트

---

## 1단계: 웹 검색 원본 결과 (`web_search()` 단독, LLM 없음)

실제 챗봇 사용자가 물어볼 법한 흔한 요리, 최근 트렌드 요리, 그리고 환각 유발용 가상의 요리명을 섞어서 구성.

## 2단계: 프롬프트 개선

1단계에서 발견한 "무관한 결과가 그럴듯하게 섞여 나오는" 문제(6, 8, 10번)를 반영해 `templates/name_search_prompts.py`의 `generate_recipe_by_name_prompt`에 다음 규칙 추가:

- 검색 결과가 요청한 이름 그 자체를 **직접** 설명해야만 실존 인정 (단어 일부만 우연히 겹치는 경우 제외)
- 브랜드 콜라보 상품명 등 "특정 레시피가 없는 것"은 비실존으로 판정
- 애매하면 무조건 비실존(false) 쪽으로 판단 (지어내는 것이 최악의 결과라는 원칙 명시)
