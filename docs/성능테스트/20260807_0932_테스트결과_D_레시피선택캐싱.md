# D. 레시피 선택 및 캐싱 (36~43번) 테스트 결과

**테스트 방식**: `nodes/recipes.py`의 `select_recipe_option`/`finalize_recipe`/`fetch_rag_recipe`, `nodes/preview_recipes.py`의 `preview_recipe_options`를 직접 호출 (그래프 전체 실행 아님). 합성 옵션 데이터로 정확히 통제. 36~42번은 실제 LLM 호출, 43번은 mock으로 LLM 없이 검증.

**요약**: 8개 중 7개 완전 일치, 1개(39번)는 코드가 아니라 문서의 기대치가 틀렸던 것으로 확인 → 문서 수정.

---

## 상세 결과

### 36. 프리뷰 목록에서 "1번" 선택 → 최초 생성
- 후보: `1.김치볶음밥 2.된장찌개`
- select_recipe_option("1번") → 김치볶음밥(opt1) 매칭 성공
- finalize_recipe → **캐시 미스**, LLM으로 신규 생성, `finalized_recipes`에 `generated:opt1` 키로 저장
- 판정: ✅ 일치

### 37. 위 상태에서 "2번" 선택 후 다시 "1번" 재선택
- select_recipe_option("2번") → 된장찌개(opt2) 매칭 성공
- finalize_recipe → 캐시 미스, 신규 생성, `generated:opt2` 저장
- select_recipe_option("1번") 재선택 → 김치볶음밥(opt1) 매칭 성공
- finalize_recipe → **캐시 적중**, 36번에서 만든 것과 **동일 객체** 반환 (LLM 재호출 없음)
- 판정: ✅ 일치

### 38. RAG 출처 옵션 선택
- 합성 RAG 레시피(recipe_id=999999, 김치찌개)로 옵션 구성
- select_recipe_option("1번") → 매칭 성공
- fetch_rag_recipe 2회 연속 호출 → **완전히 동일한 결과**, 출처 문구(`출처: 만개의레시피 (...)`) 포함 확인
- 판정: ✅ 일치

### 39. "게살볶음밥과 돼지고추장비빔밥 먹고싶어" (복합 질의)
- 후보: `1.게살볶음밥 2.돼지고추장비빔밥 3.김치찌개`
- select_recipe_option → **무효 처리(selected_number=null)**
- 1차 판정: ❌ (원본 문서는 "LLM이 알아서 하나로 판단해 매칭"을 기대)
- **원인 분석**: `option_match_prompt`에 "여러 개를 동시에 원하거나... 모호해서 하나로 특정할 수 없다면 selected_number는 반드시 null"이라는 규칙이 명시돼 있음. 즉 지금 동작은 **프롬프트 설계상 의도된 결과**.
- **문서 수정 완료**: "무효 처리(재질문)가 정상 동작"으로 기대치 변경. 사용자 확인(모호하면 재질문하는 현재 동작 유지, 옵션 1 선택) 완료.
- 최종 판정: ✅ (문서 수정 후 일치)

### 40. "쏘야볶 알려줘" (축약어)
- 후보: `1.게살볶음밥 2.소세지 야채 볶음 3.김치찌개`
- select_recipe_option → "소세지 야채 볶음"(2번) 정확히 매칭
- 판정: ✅ 일치

### 41. 목록에 없는 요리명 선택
- 후보: `1.게살볶음밥 2.돼지고추장비빔밥 3.김치찌개`
- 입력: "초콜릿 무스 케이크 줘"
- select_recipe_option → 무효 처리 (selected_option=None)
- 판정: ✅ 일치

### 42. "2번 말고 3번으로 할게" (정정 표현)
- 후보: `1.게살볶음밥 2.돼지고추장비빔밥 3.김치찌개`
- select_recipe_option → 3번(김치찌개) 정확히 매칭
- 판정: ✅ 일치

### 43. 재료 변경 후 동일 title의 요리가 다시 프리뷰에 등장
- `preview_recipe_options`를 mock LLM(같은 제목 "김치볶음밥" 반환)으로 2회 연속 호출
- 1차 테스트에서 mock 객체를 재사용하는 실수로 오탐(❌) 발생 → 매 호출마다 새 mock 객체를 반환하도록 수정 후 재검증
- 재검증 결과: 1회차 recipe_id=`dc306a51`, 2회차 recipe_id=`1119f111` — **매번 다른 uuid** 부여 확인
- 판정: ✅ 일치 (최초 실패는 테스트 스크립트 버그였음, 코드 문제 아님)
