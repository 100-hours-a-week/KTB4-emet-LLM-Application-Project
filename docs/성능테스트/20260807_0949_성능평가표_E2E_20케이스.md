## 핵심 발견: 7번 케이스 — "다른 거 없어?"가 재추천이 아니라 "선택"으로 오분류됨

**턴1** ("돼지고기, 김치, 두부 있어"): 정상적으로 4개 옵션 노출.

**턴2** ("다른 거 없어?"): 노드경로 `['query_analysis', 'select_recipe_option']` — **`reset_recipe_options`를 거치지 않고 곧바로 `select_recipe_option`으로 라우팅됨.**

```
죄송해요, 목록에 있는 번호나 요리 이름으로 다시 말씀해 주세요.

1. 두부김치
2. 김치찌개
3. 김치두부볶음
4. 돼지고기김치볶음밥
```

**의미**: `query_analysis`가 "다른 거 없어?"를 "레시피 선택"(기존 목록 중 고르기)으로 분류해버려서, 재료 흐름(`reset_recipe_options → ... → rag_adequacy_check → preview_recipe_options`)을 아예 타지 않습니다. 즉 **오늘 구현하고 단위 테스트로 40/40 통과 확인한 `shown_rag_ids`/`shown_titles` 중복 방지 로직이, "다른 거 없어?"라는 가장 자연스러운 실제 문구로는 도달조차 못 하는 상태**입니다.

원인은 `templates/analysis_prompts.py`의 `query_prompt`가 "다른 거 없어?" 같은 재요청 표현을 "레시피 추천"과 "레시피 선택" 중 어느 쪽으로 분류해야 하는지 명확한 기준이 없어서로 보입니다. 이건 문서 오류가 아니라 **실제로 고쳐야 할 분류 프롬프트/로직 문제**입니다.

## 참고: 6번 케이스 — 출처 표기 검증 미완료

RAG 옵션("두부김치", 추가 재료 없음)을 1번으로 선택했는데, 노드경로가 `finalize_recipe`(생성 경로)로 나와서 실제로는 **생성된(generated) 옵션이 선택된 것**으로 확인됨 (RAG 옵션과 생성 옵션이 우연히 같은 이름·같은 "추가재료 없음"으로 나왔고, 정렬 동률 시 어느 쪽이 1번이 될지는 보장되지 않음). 그래서 이 케이스로는 출처 표기 검증이 안 됐습니다. 대신 **9번 케이스**(이름 검색 흐름의 RAG 선택)에서 출처 표기가 정확히 확인됐습니다:
```
출처: 만개의레시피 (https://www.10000recipe.com/recipe/6937615)
```

## 케이스별 상세 (입력/출력)

### 1. 기본 재료 추천
- 입력: "계란, 대파, 돼지고기 있어"
- 출력 요약: 4개 옵션(대파 계란말이/돼지고기 계란볶음/돼지고기 대파 볶음/돼지고기 계란 덮밥), 전부 추가재료 표기 정상

### 2. 재료 추가 후 재추천
- 입력: "계란, 대파, 돼지고기 있어" → "우유도 있어"
- 재료 목록이 정확히 "계란, 대파, 돼지고기, 우유"로 갱신되고, 우유 활용 옵션(스크램블에그, 크림 볶음 등) 반영됨

### 3. 재료 제거 후 재추천
- 입력: "계란, 대파, 돼지고기 있어" → "계란 빼줘"
- 재료 목록이 정확히 "대파, 돼지고기"로 갱신, 계란 없는 옵션들로 재구성됨

### 4. 옵션 선택 → 생성 확정
- 입력: (1과 동일) → "1번"
- "돼지고기 계란볶음" 정확히 매칭, 재료/조리순서 포함한 완성 레시피 생성

### 5. RAG 매칭 많은 재료 추천
- 입력: "돼지고기, 김치, 두부 있어"
- "두부김치(추가 재료 없음)" 등 RAG 매칭이 상위에 노출됨

### 8. 이름 검색
- 입력: "된장찌개 레시피 알려줘"
- RAG에 버전이 4개 있어 전부 리스트로 노출 (다중 매칭 기능 정상 동작)

### 11. 이름 검색 - 생성 폴백
- 입력: "스페이스라면 레시피 알려줘" (가상의 요리명)
- RAG 매칭 0건 → `generate_recipe_by_name`으로 정확히 1개만 생성: "스페이스라면 (재료: 라면, 물, 계란, 대파, 김가루, 체다치즈, 후추)"

### 12. 궁합 나쁜 조합
- 입력: "감, 게 있어"
- not_cookable 판정 + 이유에 "감과 게는 함께 섭취 시 소화에 좋지 않다고 알려진 조합" 포함

### 14~16. 예외 라우팅
- "레시피 추천해줘"(재료 없음) → NONETYPE(개발 예정 안내)
- "오늘 날씨 어때?" → NONE(관련 없음 안내)
- "다이어트 식단 짜줘" → NONETYPE(개발 예정 안내)
- 셋 다 이유 설명이 상황에 맞게 정확함

### 18. 여러 개 동시 요청
- 입력: (프리뷰 후) "1번이랑 2번 둘다 궁금해"
- `option_match_prompt`의 "여러 개 동시 요청 시 null" 규칙대로 무효 처리 → D-39와 동일 패턴, 실제 그래프에서도 일관되게 재현됨

### 19. 정정 표현 선택
- 입력: (프리뷰 후) "2번 말고 3번으로 할게"
- 3번("돼지고기 계란 부침개") 정확히 매칭, 완성 레시피 생성

### 20. 쫄면 이름 검색
- 입력: "쫄면 레시피 알려줘"
- 4개 버전 전부 재료가 채워진 상태로 노출 (정규화 불량 데이터 정리 효과 확인), 당근+오이 궁합 경고도 정상 표시
