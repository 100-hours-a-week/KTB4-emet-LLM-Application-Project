## 1. 요리 이름 검색 (신규 기능)

### 1-1. RAG에 같은 요리의 여러 버전이 있는 경우
- 입력: "볶음밥 레시피 알려줘", "된장찌개 알려줘" 등 RAG에 여러 버전이 존재할 만한 이름
- 기대 결과: `judge_name_match`가 여러 후보를 매칭하면 1개가 아니라 리스트로 노출됨
  ("N. {제목} (재료: ...)" 형태로 여러 줄)
- 확인 포인트: 각 옵션의 재료 목록이 제대로 채워져 있는지 (빈 재료 없음)

### 1-2. RAG에 적합한 후보가 하나도 없는 경우
- 입력: RAG 코퍼스에 없을 법한 특이한/구체적인 요리 이름
- 기대 결과: `generate_recipe_by_name`이 딱 1개만 생성 (여러 개 생성 안 함)
- 확인 포인트: 생성된 레시피가 실제로 사람이 먹을 수 있는 정상적인 요리인지 (괴식 아님), 30분 이내 조리 가능한지

### 1-3. 정규화 불량 후보 필터링 (filter_valid_candidates)
- 입력: "쫄면 레시피 알려줘" (오늘 재료 없는 쫄면 2건을 정리하기 전 실제로 문제됐던 케이스)
- 기대 결과: RAG 후보 중 title/ingredients/steps 중 하나라도 비어있는 후보는 이름 판정 전에 제외되어, 노출되는 옵션은 전부 재료 정보가 채워져 있어야 함
- 확인 포인트: (사용자가 이미 확인 완료 — 쫄면 4개 RAG 결과 정상 출력됨)

### 1-4. 이름 검색 후 선택 → 확정
- 1-1 또는 1-3에서 나온 옵션 중 하나를 번호/이름으로 선택
- 기대 결과: 재생성 없이 캐시로 즉시 레시피 본문(재료+조리순서) 확정 출력
- 확인 포인트: `select_recipe_option` 정렬 기준(재료 수 오름차순)과 노출 시 번호가 일치하는지

### 1-5. 쿼리 타입 분류 정확도 (회귀 확인)
- 입력: "계란볶음밥 만드는 법", "계란이랑 밥 있는데 뭐 해먹을까" 등 이름 검색 vs 재료 추천 헷갈리기 쉬운 케이스
- 기대 결과: 전자는 "레시피 이름 검색", 후자는 "레시피 추천"으로 정확히 분류
